# Coding Agent M3 API 与 UI 完成说明

> 完成日期：2026-08-28  
> 范围：真实 Agent 事件展示、前端响应校验、SSE 恢复、整页刷新恢复及终态一致性。

## 1. 完成内容

M3 继续复用 M2 的任务、事件和工具结果契约，没有新增工具执行入口，也没有在前端重复实现工具层输出上限。

- `ToolEventCard.vue` 分别展示工具开始、成功、失败、取消、合成纠偏结果、调用 ID、参数和结构化结果。
- `FileChangeCard.vue` 展示相对路径、动作、修改前后字节数、Diff、Diff 截断和临时文件清理状态。
- `CommandResultCard.vue` 展示命令、退出码、终止原因、耗时、进程清理状态以及有界 stdout/stderr。
- `types.ts` 为八类事件建立判别联合，并在运行时逐类校验信封和 payload；超限事件使用 M2 的 `payload_truncated` 信封展示预览。
- REST 响应同样在进入页面状态前校验 Task 和 Metadata，错误响应不会被当成合法任务。

页面只使用 Vue 文本插值和 `pre` 展示模型、文件及命令内容，不使用 `v-html`，也不会在浏览器执行事件中的代码。

## 2. SSE 与恢复语义

前端改用 Fetch 读取 SSE，以便可靠区分 HTTP 204、404 和 410，同时仍按递增事件 ID 去重。

| 情况 | 页面行为 |
|---|---|
| 短暂断线或 5xx | 从最后收到的事件 ID 按 0.5、1、2、4、8、15 秒上限退避重连；不创建新任务 |
| 204 | 事件流已到终态；停止重连并查询任务状态 |
| 410 | 原游标已退出有界历史窗口；清空不完整时间线，从服务器当前保留窗口重新回放并明确提示 |
| 404 | 任务不在当前进程内存中；清除本地任务 ID，并说明服务重启后的历史不能恢复 |
| 非法事件 | 停止自动重连并显示契约错误，避免把未知数据写入 UI 状态 |

浏览器把最近任务 ID 保存在 `localStorage`。整页刷新后先调用任务查询接口，再从游标 0 回放服务器仍保留的事件。这里持久化的只是引用，不是任务数据；后端重启后任务仍按既有内存边界丢失，页面不会自动重复提交。

## 3. 终态一致性

`task_completed` / `task_failed` 到达后，页面先停止事件流，再以 `GET /api/tasks/{id}` 为权威状态刷新最终结果。若 SSE 终态与查询状态不一致，页面会显示明确错误而不是静默覆盖。

后端契约测试覆盖：

- 完成后断线重连只回放缺失事件，末游标返回 204；
- 大型 Tool/File/Command payload 被事件层裁剪后仍是合法 JSON，终态事件仍保留；
- 成功和结构化失败的 SSE 终态均与任务查询一致；
- 新应用进程不会声称可以恢复旧进程的内存任务。

## 4. 边界

- 后端仍是单进程、单活动任务、内存历史；没有数据库持久化、跨进程恢复或用户取消 API。
- 410 后只能恢复当前保留窗口，不能重建已淘汰事件。
- 工具结果、Diff、命令输出先受工具层既有上限约束；事件层只负责独立的传输/历史上限，前端不再裁剪一份业务结果。
- 真实供应商兼容性、真实 Bug Demo 连续成功率属于 M4，不以确定性 M3 测试替代。

## 5. 验证入口

- `tests/test_m3_api_ui_contracts.py`：断线回放、大载荷、服务重启、成功/失败终态一致性。
- `npm.cmd run typecheck`：严格 TypeScript 与 Vue 模板检查。
- `npm.cmd run build`：生产构建。
- `scripts/smoke_browser.cjs`：启动前后端并安装可选 Playwright 后，可检查 scaffold 链路、刷新恢复与窄屏布局。
